只使用四个文档相关技能：`docx` / `pdf` / `pptx` / `xlsx`。不要调用其他 doc-* 命令或 skill，也不要调用 `doc_import` / `doc_convert` / `doc_template_render`。
用户参数：$ARGUMENTS

规则：
- 若输入包含 .docx/.pdf/.pptx/.xlsx 文件路径，先用对应 skill 读取/提取内容，再继续流程。
- 任何导出/修改 .docx/.pdf/.pptx/.xlsx 都必须使用对应 skill；不要使用 pandoc 或 doc_convert。
- 若缺少对应 skill，提示用户先运行 `/skill-init` 或 `/skill-install`。
- 其他文本内容在会话中用 Markdown 组织。

流程（必须按顺序执行）：
1) 明确目标、受众、交付格式、是否多文档；列出缺失信息并提问。
2) 输出 `doc.flow.v1` 的 YAML（包含 domain、doc_catalog、output_format、missing_inputs、next_action）。
3) 用户确认后，生成各文档的 Markdown 大纲/骨架，并再次确认。
4) 用户确认后，填充完整正文（Markdown）。
5) 如需输出 .docx/.pdf/.pptx/.xlsx，加载对应 skill 并按其指引生成文件；同时给出生成结果摘要与文件名/路径。
6) 如仅需文本/Markdown，直接输出最终内容并给出摘要。

输出要求：每个阶段都清晰标注（Phase A/B/C...），多文档输出需按 doc_type 分组。
