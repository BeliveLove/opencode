先调用 `skill` 工具加载 `doc-flow`，并严格按技能契约输出。
用户参数：$ARGUMENTS

规则：
- 如果参数里包含/看起来像文件路径（.md/.txt/.docx/.pptx/.xlsx/.pdf），先用 `doc.import` 导入后再判断。
- 领域判断优先根据仓库信号；本仓库为软件工程领域时直接进入该域。
- 输出文档清单时允许多选，优先推荐仓库已有模板/文档类型。
- 不要擅自定“必须产出”的文档；用“建议/可选”并让用户确认。
- 质量优先：图表/表格必须有图注/表注 + 解释 + 文内引用；编号步骤必须保序；禁止用内联破折号模拟列表。
- `doc.template.render` 是工具，不是 skill，禁止调用不存在的 skill（例如 `doc-template-render`）。
- 内置模板优先使用（模板ID如下）；若无匹配模板，可让 `doc.template.render` 基于领域 + doc_type 自动生成模板：
  doc.default, tech.prd, tech.tdd, tech.sdd, eng.requirements_analysis, eng.feasibility_study,
  qa.test_plan, ops.runbook, ops.postmortem, security.threat_model,
  eng.release_notes, mgmt.meeting_minutes, mgmt.weekly_report, legal.contract_review_notes.
- 每个 doc_type 必须落地一个模板 Markdown 文件（template_md）；若用户未指定路径，默认写入 `.opencode/doc/templates/<doc_type>.template.md`。
- 若未指定模板且无匹配内置模板类型，使用 `doc.template.render` 自动推断模板（必要时再用 `doc-outline` 补细节）。
- `doc-style` 是 skill，必须在填充正文后调用以整理样式与元信息。
- 如果输入是 .doc/.docx 且需要样式统一：先用 `doc.convert` 转成 .md，再走 `doc-style`，最后再 `doc.convert` 回 .docx。
- 如果输入是 .md，直接 `doc-style` 后再 `doc.convert` 到 .docx。

流程（必须按顺序执行）：
1) 输出 `doc.flow.v1` 的 YAML（包含领域 + 文档清单 + 推荐项 + 缺失信息 + template_md/reference_docx）。
2) 询问用户选择需要的 doc_type（支持多选）。如果用户已明确文档类型，直接进入下一步。
3) 对每个 doc_type 生成骨架：
   - 有内置模板则用 `doc.template.render`
   - 无内置模板则用 `doc.template.render` 自动推断模板；需要更细时再用 `doc-outline`
4) 为每个 doc_type 写入模板 Markdown 文件（template_md）：
   - 用户已提供模板路径：直接使用并必要时 `doc.import` 验证内容。
   - 使用 `doc.template.render` 输出并写入 template_md（无内置模板时用自动推断模板）。
   - 若仅有 `doc-outline` 结果，将 outline 转成 Markdown 骨架再写入。
5) 由 template_md 生成 reference docx（template_docx）：调用 `doc.convert` md->docx，后续导出时用 `--reference-doc` 引用。
6) 汇总所有骨架/模板，请用户确认/补充缺失信息。
7) 质量数据准备检查：收集图表/表格清单、数据来源、口径/时间范围、关键指标值；缺失项写入 open_questions 并要求用户确认。
8) 用户确认后，对每个 doc_type 调用 `doc-fill` 生成正文。
9) 询问并收集样式与元信息（字体/字号/行距/目录层级/作者/版本/日期/状态/是否提供 reference docx/图表格式/首行缩进）。如用户未提供，直接使用默认样式并说明默认值（默认图表格式：mermaid，首行缩进 2 字符）。
10) 先调用 `skill` 工具加载 `doc-style`，再统一整理（元信息 + 标题层级 + 目录 + 排版），输出 styled_markdown。
11) 汇总 styled_markdown 并执行 `doc-review`，给出阻塞项/缺失项（图表图注/解释/引用、列表格式、表格化、编号顺序、数据来源）。
12) 用户确认后，若需要导出 Word：
   - 输入为 .doc/.docx：`doc.convert` docx->md -> `doc-style` -> 如含 Mermaid 则 `doc.diagram.render` -> `doc.convert` md->docx（附带 toc 与 reference docx）。
   - 输入为 .md：`doc-style` -> 如含 Mermaid 则 `doc.diagram.render` -> `doc.convert` md->docx（附带 toc 与 reference docx）。
13) 如涉及对外发布/分享，导出前先运行 `doc.redact`。
14) 导出后可选质量校验：`doc.import` 回导出文档并再次 `doc-review`，确认目录/列表/表格/图注无回退。

输出要求：每个阶段都清晰标注（Phase A/B/C...），多文档输出需按 doc_type 分组。
